# PiMate mobile

Expo（SDK 57、expo-router）のアプリです。Android優先で作っています。見た目は [docs/design/](../../docs/design/README.md) のモックに合わせます。ライト / ダークは起動時の OS の設定に従います（起動中に OS 側で切り替えた場合は次の起動から。[#23](https://github.com/phni3j9a/PiMate/issues/23)）。ダークも色の役割は同じで、線や影ではなく面の濃淡で区切ります。本文は 15px です。

アイコン類は [icon kit](../../docs/design/icon-kit/README.md) の書き出し済み素材を `assets/brand/` にコピーして使います（正本はキット側）。Android はライト版の adaptive icon＋テーマアイコン用の単色、iOS は Light / Dark / Tinted。スプラッシュはアプリの背景色にマークを載せ、ライト / ダークで配色を切り替えます。通知は白いシルエット。アプリ内ではペアリングの最初の画面と設定のバージョン表示だけにマークを置きます。差し替えには APK の再ビルドが必要です（OTA では変わりません）。

現在の配布版は Android 0.1.5 / PCパッケージ0.1.7 です。プロバイダーのログイン・利用枠には PC 0.1.7 以上、スラッシュコマンド・セッションツリーには PC 0.1.6 以上が必要です。更新後は Pi を再起動または `/reload` し、`/pimate status` から必要に応じて Host を再起動してください。

既知の問題: ライトテーマで Android のナビゲーションバーのアイコンが見えない場合があります（[#46](https://github.com/phni3j9a/PiMate/issues/46)）。

## プロバイダーへのログイン／ログアウト

チャットで対象の Pi を開き、**設定 → プロバイダーのログイン**から OpenAI・OpenAI Codex・Anthropic を操作できます。OpenAI は API キー入力のみ、Anthropic は API キーにも対応します。スマホのブラウザを使い、Codex はデバイスコード、Anthropic は表示コードの貼り付けで完了します。OpenAI（`openai`）の ChatGPT ログインは削除しましたが、Codex のログインは引き続き利用できます。

認証は PC の Pi と共有です。ログアウトは確認後に保存済み情報だけを削除し、環境変数やプロバイダー側での失効操作は変更しません。Android 0.1.5 / PC 0.1.7 以上が必要で、アプリ・Host・対象 Pi の RC をすべて更新してください。手順・保存先・切断時の扱い・検証範囲は [プロバイダー認証](../../docs/provider-auth.md) を参照してください。

開発用 fake Host でも認証フローを確認できます。`POST /_dev/auth?complete=1` は Codex の完了、`expire=1` は期限切れ、`fail=1|0` は保存時の成功／失敗、`saving=ms` は保存待ち、`refresh=1|0` はモデルへの反映失敗、`old=1|0` は旧 RC、`oldHost=1|0` は旧 Host（再接続後に反映）、`badurl=1|0` は不正 URL を再現します。対象は既存の `i=<instanceId>` で指定できます。入力を保存・ログ出力せず、ブラウザ用 URL とコードもダミーなので**実際のアカウント認証には使わないでください**。

## できること

M1:

- ペアリング: QR読み取り・リンク貼り付け・`pimate://pair?...` ディープリンク → 確認 → 登録（PC側は `pimate pair`。[packages/pimate](../../packages/pimate/README.md#スマホとの接続m1) を参照）
- ドロワー（左上のボタン、またはチャットのどこからでも右へスワイプ。画面端は Android の「戻る」と競合するため）: マシンごとのPi一覧、入力待ちは「要対応」にまとめる、設定への入口
- チャット: 履歴、逐次表示、「考えた」行、ツール行（開閉）、箇条書き程度の簡易整形、送信・停止、作業中の送信は常に「割り込む」（steer）、待機中は通常送信。「後で伝える」や送信タイミングの切り替えはありません。割り込みは作業の区切りで反映され、受け付け後も本文に現れるまでは「割り込み待ち」と表示
- 割り込みが本文へ反映される前に停止した場合は、本文＋画像を送信単位ごとの未確認行に残します。PC の入力欄に戻っている場合があるため、履歴を確認してください。編集中の下書きや添付は変更しません。「下書きへ戻す」は入力欄の本文と添付が両方空、かつ同じセッションのときだけ使えます。戻しても自動では送信しません。下書き・未確認行はメモリ内のみで、アプリ終了を越えて保持しません。未確認行は Pi の選択変更でも消えます。
- 接続: 自動再接続（待ち時間を伸ばしながら）、前面復帰時の再接続と再購読。送れたか不明な送信は自動で再送しない
- 設定: ペアリング済みマシンの状態と削除

M2:

- 新しい Pi（ドロワー上部の「新しい Pi を起動」）: マシン、最近使ったフォルダ（実行中の件数・最終利用）か手入力のパス、「このフォルダを信頼する」、モデル（そのマシンで動いている Pi から取得。なければ「Pi の既定」）、最初のメッセージ。起動後は一覧に現れるのを待って開く。最初のメッセージが送れなかったときは再送せずにそう表示する
- 質問への回答: select / confirm / input / editor をチャット内のカードで回答（回答は1回だけ送り、送信先の Pi・セッションを確かめる）。PC で回答されたら短い注記を残す
- PC でしか操作できない画面（Extension の独自 UI など）は「PC のターミナルで操作が必要です」カードと `pimate attach` のコマンド（コピー可）を表示
- セッションのメニュー（ヘッダーの「…」）: 統計（メッセージ・トークン・コスト）、新しいセッション、過去のセッションを開く、ここから分岐（ユーザーのメッセージを選ぶ。選んだ文は入力欄に入る）、コンテキストを圧縮、起動元・PC の接続状態・attach コマンド、この Pi を終了（確認あり）
- モデル・Thinking（入力欄のモデル名）: プロバイダーごとのモデル、そのモデルで使える Thinking レベル、コンテキスト使用量とコスト、圧縮。変更は PC の Pi にも反映される。「お気に入り」は PC の Pi の scoped models（`/scoped-models`・`enabledModels`、Ctrl+P で切り替えるモデル）と共通で、PC の `/model` と同じくお気に入りがあれば「お気に入り」から開き「すべて」に切り替えられる。☆ で追加・削除するとグローバル設定に保存（起動中の PC の Pi の Ctrl+P は再起動後に反映）。新しい Pi のモデル選択もお気に入りから。PC パッケージ 0.1.2 以前では ☆ を出さない（[#23](https://github.com/phni3j9a/PiMate/issues/23)）
- 利用枠（Android 0.1.5 / PC 0.1.7 以上、[#53](https://github.com/phni3j9a/PiMate/issues/53)）: Codex（`openai-codex` の ChatGPT ログイン）と Claude（Pro/Max ログイン）の 5時間・週間の使用率とリセット日時、取得時刻を表示する。Pi の通常の応答に含まれる値だけを使い、利用状況 API への追加リクエストやポーリングはしない（各サブスクの最初の応答までは表示されない。他の端末での利用は次の応答まで反映されない）。リセット日時を過ぎた値は「—」にする。Codex は 100% でも追加クレジットで応答が続くことがあるため、使えるかどうかの判定には使わない。API キー利用は対象外。PC の RC が未対応なら更新を案内する
- 使用状況ゲージ（[#59](https://github.com/phni3j9a/PiMate/issues/59)）: 入力欄のモデル名の横に、コンテキスト（書類アイコン）・Claude・Codex（各社ロゴ）の円形ゲージを常時表示する（数字なし）。利用枠の円は 5時間・週間のうち使用率が高い方で、80% 以上で黄、95% 以上で赤。未取得・リセット済み・旧 RC は灰色の点線にし、0% と表示しない。タップで「使用状況」シート（コンテキストと圧縮、各枠の使用率・リセット時刻と残り時間・取得時刻）を開く。モデルシートはモデルと Thinking だけ。利用枠は同じ PC の Pi で最も新しい観測を使う（RC がランディレクトリで共有。バックグラウンドのサブエージェントの応答も反映、フォアグラウンドのサブエージェントは Pi の拡張イベントが届かないため対象外。別アカウントの値も区別しない）。円はリセット時刻とアプリの復帰時に更新する
- PC 側の変化に追従: `/resume` などでセッションが変わったら区切りを表示し、下書きがあれば送信前に確認を求める。モデル・Thinking の変更も反映

M3（表示）:

- ターンの折りたたみ: 終わったターンの「考えた」行・ツール行・途中の文は「18秒 作業 · ツール 4 回」の1行にまとまり、タップで開閉する（最後の回答と使用量は常に表示。作業中のターンは開いたまま）。時間はアプリが開始から `agent_settled` までライブで観測できたターンだけ計測し、履歴・途中参加・途中の再接続では秒数を省く（assistant の時刻は生成開始であり、完了時刻ではない）。ファイルを変えたターンは「+a −b」（差分がなく書き込んだ内容しか分からないときは「N ファイル」）を添え、タップで変更画面を開く
- ツール行の右端: edit / write は「+a −b」、read は行数、bash などは所要時間、失敗は「エラー」。「考えた」の秒数はアプリが始まりから見ていたときだけ出す（履歴では数字を作らない）。edit / write を開くと出力の代わりに差分を表示する
- 変更画面（ターン要約の「+a −b」、セッションのメニューの「変更を見る」）: 「このターン」「セッション全体」の切り替え、ファイルごとの A/M・+/−・開閉、差分（行番号つき、追加は青・削除はコーラル）。同じファイルへの複数の変更は順に並べて表示し、1つの差分にまとめない。コピーは表示中の差分（unified diff）をまとめてコピー。「この変更について依頼」はチャットに戻り、「このターンの変更（src/greet.ts ほか 2 ファイル）について：」を入力欄に入れる（送信はしない）
- 差分の出どころ: edit は Pi の `details.patch`、write は RC が付ける `details.pimate`（`write_diff`）。それがない古い履歴や、大きすぎ・バイナリ・読めない・同時に複数の変更があった場合は、そう書いたうえで書き込んだ内容を表示する（新規ファイルとは言わない）
- 停止ボタンはターンの実行中だけ表示（ターン外の Extension の質問では出さない）。中断したメッセージの「0 in · 0 out」は出さない
- シートはキーボードを避ける。新しい Pi のモデル選択にも検索。セッションのメニューの操作が断られたときはシートの中に表示する
- 回答の Markdown（[#23](https://github.com/phni3j9a/PiMate/issues/23)）: `marked` の lexer で解析し、表示は自作（`src/lib/richText.ts` / `src/components/chat/RichText.tsx`）。見出し（h1〜h3 の大きさ）、リスト（入れ子・番号・チェックボックス）、引用、表（横スクロール）、区切り線、太字・斜体・取り消し線、インラインコード、http(s) リンク（アプリ内ブラウザ）。`これは**「太字」**です` のように CommonMark が太字にしない日本語の書き方も太字にする。コードブロックは折り返し表示で、言語名とコピーボタンつき（ストリーミング中の閉じていない ``` もコード）。回答を長押しで全文（Markdown）をコピー（部分選択はできない）

同じファイルへの変更は `./`・`..` を POSIX の規則で正規化して集約する。インスタンスの cwd が分かるときは絶対・相対パスも同一視する（シンボリックリンクの解決はしない）。同じ範囲内で新規作成したファイルは、後で編集しても A のまま。

M4（サブエージェント。RC が pi-subagents / 公式サンプルを正規化したもの。[docs/subagents.md](../../docs/subagents.md)）:

- 入力欄の上の要約1行「サブエージェント 2 実行中 · 1 完了」（待ち・一時停止・失敗・停止も数える）。どれかが動いている間は親の状態と関係なく出し、全部終わった後も次のプロンプトを送るまで残す。タップで一覧
- 一覧（シート）: トークン・コスト・バックエンド、実行中の実行ごとに「並列 · バックグラウンド」「チェーン 1 / 3」などの見出しと、バックエンドが許す停止だけ（停止… / 中断… / すべて停止…、確認あり）。子ごとに状態の印・名前・エージェント・経過時間（スマホの時計で計算し、開いている間だけ進める）・今の作業（`read  src/api/client.ts`）か「完了 / 失敗 · 理由 / 待ち · 質問 / 一時停止」。終わった実行は「以前の実行」に「完了 · 18分前」で並ぶ。pi-subagents のときだけ `/subagents-fleet` の案内
- 子の画面（`/subagent`）: 名前・エージェント・モデル・コスト（チェーンは「チェーン 1 / 3」）、状態と経過時間、「親の Pi からの依頼」とチェーンの並び、作業記録（チャットと同じ行。開くとき・その実行の更新が届いたとき（1秒に1回まで）・終わったときに cursor で差分だけ取る。一定間隔のポーリングはしない）。送った指示は「あなた · 割り込み」などの注記つき
- 操作は `actions` にあるものだけ: 割り込む（steer）のみ（follow_up だけの子には入力欄を出さず、割り込み未対応と表示）、停止（stop_child、なければ実行全体の stop / interrupt）、終わった子への「続きを依頼」（resume。新しい実行に移り、前後の実行へのリンクを出す）。失敗は画面内に表示する。公式サンプルは見るだけで、「すべて停止…」（abort_parent）は親の Pi も止まると明記する
- 質問中の子: 質問を黄色で表示し、回答は親の Pi を通す（「チャットで回答」で入力欄に下書きを入れて戻る。子に直接は答えない）。`waiting` にはidle-attentionも含まれるため、質問本文が分からない場合は「確認が必要です」として親のチャットへ案内する
- 操作成功は短い日本語で表示する（backendの長い返信・内部パス・送った依頼の再掲で入力欄を埋めない）。steerの受領と子への反映は別で、実際の受信は作業記録で確認できる
- チャットの `subagent` ツール行: RC が実行を知っているときは「subagent reviewer × 3 · 並列 … 2 実行中 ›」になり、終わったターンでも折りたたまない。タップで一覧（子が1人なら子の画面）。知らないときは普通のツール行
- ドロワー: 一覧の件数から「~/work/api · サブエージェント 2 実行中」。子が待ち状態なら親が待機中でも「要対応」に出す（開いている Pi なら質問の文も）。失敗は履歴の件数なので出さない

M5c（アプリ / Host 0.1.1）:

- 設定で明示的にオンにした場合だけ、入力待ち・完了・失敗を端末内に通知。通知権限もその時点で要求します。子の完了は通知しません。
- 接続中の全 Pi が対象。対象チャットを表示中は抑制。通知タップで対象の生存・セッションを確かめ、親チャットへ移動します。初期同期・履歴・再接続から通知を再発行しません。
- **アプリ終了・OS による休止・切断中は受信できません。** プッシュ配信や常時バックグラウンドサービスはありません。
- 古い Host ではチャットのみ。通知のためには PC パッケージを更新し Host を再起動してください。

詳しい通知対象・安全策・ネイティブ検証・未検証事項は [docs/notifications.md](../../docs/notifications.md)。

## チャットの / コマンド（[#37](https://github.com/phni3j9a/PiMate/issues/37)）

- 入力欄の先頭に `/` を入れると、入力欄の上に名前・説明・種類の候補が出ます。空白を入れるまでは前方一致で絞り込み、タップで `/name ` を挿入します（タップだけでは実行しません）。引数を足して送信できます。
- RC の Extension・プロンプトテンプレート・Skill（`/skill:name`）を利用できます。コマンド一覧は Pi インスタンスごとにメモリ内でキャッシュし、インスタンスを開き直したとき、セッション切替、PC の `/reload`、再接続後に取り直します。取得失敗は候補内の「再試行」で再取得できます。内部管理用の `/pimate`・`/pimate-session` とその重複名は表示しません。
- `/model` は既存のモデル・Thinking シート、`/resume` は過去のセッション、`/fork` は分岐元メッセージの選択を開きます。`/new` と `/compact` はセッションメニューと同じ操作、`/tree` はセッションツリーを開きます（`snapshot.sessionTree` の RC のみ）。アプリ操作は引数・画像なしで送信してください（付いている場合は実行せず下書きを残します）。対応する画面のない組み込みコマンド（`/reload` など）は候補に出しません。
- 既知の RC コマンドだけ `expandTemplates:true` で送信します。Extension は作業中も即実行され、RC の `deliveredAs:"command"` を受け取ったら送信待ち・履歴待ち表示を残しません。Extension への画像添付は拒否します。テンプレート・Skill は Pi で展開して通常送信 / キューへ入れます。展開前の本文は履歴と一致しないため、通常送信の仮メッセージは残さず Pi の実履歴を表示します。
- 未知の `/name` はモデルへ送らず、入力欄の近くに説明を出して下書きを保持します。対象は先頭トークンが `/[\w:.-]+` に一致する場合だけで、`/home/x` のようなパスや文章内の `/name` は従来どおり送れます。コマンド一覧取得中も、未確認のコマンドは送信しません。
- `snapshot.slashCommands === true` の RC が必要です。古い RC では候補・判定を有効にせず従来のテキスト送信を維持します。PC パッケージ更新後は対象の Pi を再起動 / 再読み込みしてください。通信断などで実行結果が不明なときは下書きを保持し、コマンドも自動再送しません（Extension は履歴に残らないため、必要なら PC や操作結果を確認してください）。

単体テストで判定・絞り込み・挿入、組み込み操作への割り当て、キャッシュ更新、RC の判定、outbox の除去と非再送を検証しています。候補 UI とキーボード操作は Pixel 3 の実機で確認済みです（[確認範囲と限界](../../docs/slash-tree-steer-android-verification.md)）。

## 親 Pi への画像添付（[#31](https://github.com/phni3j9a/PiMate/issues/31)）

- 入力欄の「＋」で OS の写真ピッカーを開き、1枚だけ選択。サムネイル横の × で削除、＋ で変更できます。古い Android では OS が画像に絞ったファイル選択画面を開く場合もあります。カメラ撮影・一般ファイルの添付・子への画像送信・拡大ビューアはありません。
- 選択後は長辺最大 1600px の JPEG（品質 0.85）に変換し、512 KiB を超える場合は添付せず説明を出します。画像だけでも本文つきでも送信でき、画像つきの本文は 32,768 文字以内。準備中は送信できません。
- 作業中も常に「割り込む」です。画像は受付通知と反映までの「割り込み待ち」を表示し、本文には Pi の実履歴が届いた画像を表示します。Pi が画像や寸法注記を変換することがあるため、仮の送信済み表示は残しません。送信先のセッションが変わった画像だけの下書きにも確認が必要です。写真選択中に送信先が変わった場合は、遅れて返った写真を添付しません。
- Android 0.1.3 / PC パッケージ 0.1.4 以降。PC 側 RC の `snapshot.promptImages === true` が必須。未対応の RC では画像を送らず、PC パッケージ更新と Pi 再起動を案内します（Host の再起動だけでは既存 Pi の RC は更新されません）。テキストのみの送信は従来どおり。選択中のモデルも画像対応である必要があります。
- 失敗・届いたか不明な場合は本文と画像を保持し、自動再送しません。成功確認前に履歴へ挿入しません。返信待ちに下書きを編集した場合、送信済みの本文・画像と両方一致しない限り消しません。
- 通信切断で結果が未確認の画像は、Pi が再変換すると自動照合できない場合があります。その場合は下書きを保持し、手動の履歴確認を案内します。画像や本文の類似だけで配信済みと推測しません。
- 履歴は各ユーザーメッセージの最初の JPEG/PNG/WebP（512 KiB 以下）をプレビューします。履歴全体では画像の decoded 合計を 2 MiB まで、最新側から優先します。サイズ・形式・合計上限で表示できないものや複数枚の残りは、本文を残したまま画像件数と表示制限を示します。Pi の元のセッションは変更しません。
- 下書きは本文と同じくメモリ内だけで、アプリ終了を越えて保存しません。表示画像もディスクキャッシュしません。ただし OS ピッカー / Expo の変換処理は一時 cache ファイルを作ります。写真ライブラリ全体の権限は要求せず、Android のストレージ/メディア権限とマイク権限も遮断。既存の QR ペアリング用 CAMERA 権限・説明文は維持しています（picker の `cameraPermission:false` はこの権限も遮断するため使いません）。

ネイティブ依存を追加したため APK の再ビルドが必要です。単体テスト・型検査・署名付き APK ビルドを検証。Pixel 3 + fake Host で写真選択・サムネイル・削除・画像のみ送信・履歴表示を確認し、APK の権限も確認しました。レビュー後の最終 APK は Android API 35 エミュレーターでも確認済み。割り込み / 後で伝えるの送信パラメータ、画像受付通知、エラー時の本文・画像保持、切断後の自動再送防止、旧 RC の案内、ライト / ダークと幅約366dpの配置を確認しました（[確認範囲と限界](../../docs/image-steering-android-verification.md)）。Pi 実プロセス + ローカル faux provider の E2E では、画像配送・モデルの 1024px 再変換・寸法注記付き履歴を確認しています。商用の実モデルへの画像送信、iOS は未検証です。

### セッションツリー

セッションのメニューの「セッションツリー」から、同じセッションの分岐と現在位置を確認できます。「ユーザーのみ / すべて」を切り替え、メッセージを選ぶとラベルの保存・解除と「ここへ移動」が使えます。既存の「ここから分岐」は別セッションを作る操作のままです。入力欄の `/tree` からも開けます。

- 移動は実行中には受け付けません。離れる枝を要約するか選べます。要約は LLM を使い、時間と利用料金がかかります。進行中・失敗・取消は操作シート内に表示します。
- 移動後は履歴を再取得します。ユーザーメッセージを選ぶと直前まで戻り、元の枝は残ります。入力欄が空なら選んだ文の全文が戻ります（既存の下書きは上書きしません）。画像は入力欄に戻しません。
- 表示は最大1,000件、本文160文字・ラベル200文字まで。ツール結果・状態変更は畳み、一部を省略した場合は画面で知らせます。省略された全体は PC の `/tree` で確認してください。
- `snapshot.sessionTree: true` の RC のみ入口を表示します。古い PC パッケージでは更新後に Pi を再起動してください。

ツリー・割り込みのみ（停止後の「下書きへ戻す」を含む）は Pixel 3 の実機で確認済みです。キーボード表示中の操作シートのスクロールなど、未確認の項目は [確認範囲と限界](../../docs/slash-tree-steer-android-verification.md) を参照してください。

## Android APK のビルドと配布（M5b）

Expo Go / Metro なしで動く、署名済み universal release APK をローカルで作ります。`android/` は CNG の生成物（Git 管理外）です。ネイティブ設定は `app.json` / `app.config.js` と config plugin に置き、生成後の手編集はしません。

### 準備

- Node.js 22.18 以上、`npm ci`（リポジトリルート）。
- **JDK 21**（JRE だけでは不可）。`JAVA_HOME` を JDK のディレクトリに設定。
- Android SDK: `platform-tools`、`platforms;android-36`、`build-tools;36.0.0`、`ndk;27.1.12297006`、`cmake;3.22.1`。SDK のライセンスに同意しておく。
- `ANDROID_HOME` を SDK の場所に設定（既定 `~/Android/Sdk`）。root 所有 SDK に不足がある場合は sudo で変更せず、ユーザー所有 SDK に cmdline-tools と必要なパッケージを入れる。

```sh
# リポジトリルート
npm ci
export JAVA_HOME=/path/to/jdk-21
export ANDROID_HOME="$HOME/Android/Sdk"
npm run build:android -w @pimate/mobile
```

スクリプトは `expo prebuild --platform android --clean --no-install` → Gradle `:app:assembleRelease` を実行し、署名検証結果・証明書 SHA-256・APK SHA-256 を表示します。初回は SDK/Gradle/Maven のダウンロードと全 ABI のコンパイルに時間がかかります。既定の Gradle 並列数は 2（`PIMATE_GRADLE_WORKERS` で変更可）。R8/resource shrink は現時点では有効化していません。

出力は `apps/mobile/dist/pimate-0.1.5.apk`。`versionName` は `app.json` の `expo.version`、`versionCode` は `major * 1_000_000 + minor * 1_000 + patch`（0.1.0 → 1000、各要素 0〜999 の安定版のみ）です。更新ごとに version を増やします。ソース・依存 lockfile・JDK/SDK・同じ署名鍵から再構築できますが、APK のバイト単位の一致を保証するものではありません。

### 署名鍵を必ずバックアップする

初回のみ `~/.config/pimate-release/`（`PIMATE_SIGNING_DIR` で変更可、**リポジトリ外必須**）に次を作ります。

- `pimate-release.jks`: RSA 3072 bit のリリース署名鍵
- `signing.properties`: keystore の絶対パス、alias、ランダム生成したパスワード

ディレクトリは 0700、両ファイルは 0600。パスワードはログや生成 Android プロジェクトへ書き出しません。既存の片方だけがある場合はエラーにして、鍵を勝手に再生成しません。`scripts/release-signing.gradle` がビルド時に外部 properties を読み、Expo の debug key による release 署名を置き換えます。

**この2ファイルを暗号化して安全な別の場所にバックアップしてください。失くすと、公開済み APK と互換の上書き更新を署名できません。** 別 PC に復元したら `signing.properties` の `storeFile` を復元先の絶対パスへ修正します。鍵・properties・パスワードは commit、Issue、CI ログ、Release 添付に含めません。

### インストール・リリース

利用者は [GitHub Releases](https://github.com/phni3j9a/PiMate/releases) の `app-v…` から APK を取得します。Android の「不明なアプリのインストール」を、使ったブラウザ／ファイルアプリに対して許可し、APK を開きます。Tailscale に PC とスマホを接続したら、PC の Pi で `/pimate setup` → PiMate で QR 読み取り → マシンを確認してペアリングしてください。カメラ権限は QR 読み取り時だけ要求します。通信は Tailscale 内の HTTP/WS のため Android の cleartext 許可を明示しています。Host を公共ネットワークに公開しないでください。

開発者の実機インストール:

```sh
adb -s <serial> install -r apps/mobile/dist/pimate-0.1.5.apk
```

公開担当者は検証済み commit を push し、APK と SHA-256・署名証明書 fingerprint を確認してから Release を作ります。

```sh
gh release create app-v0.1.5 apps/mobile/dist/pimate-0.1.5.apk \
  --target <検証済みcommit> --title 'PiMate Android 0.1.5' --notes-file <リリースノート>
```

タグは必ず **`app-v`** 接頭辞にします。PC パッケージ用 `v*` タグの release workflow を起動させないためです。新規版を出す前に既存 `app-v…` Release と署名を確認し、同じ version/tag の APK を黙って差し替えないでください。

実機検証結果と制限は [M5b 検証記録](../../docs/m5b-android-verification.md) を参照してください。

### PCのPiなしで画面を確認する

開発用の偽Host（アプリには含まれません）があります。決まった内容のPi一覧と会話の流れを返します。

```bash
node apps/mobile/scripts/dev-fake-host.mjs --port 47800   # ペアリング用リンクとExpo Go用ディープリンクを表示
adb reverse tcp:47800 tcp:47800
# スマホから「md」で始まるメッセージを送ると Markdown の見本（見出し・リスト・表・引用・コード）を返す
curl -X POST http://127.0.0.1:47800/_dev/turn             # PCで打ったときの1ターンを再生（read / edit / write / bash。drop / offline?s=20 なども）
curl -X POST "http://127.0.0.1:47800/_dev/ask?kind=select" # 質問を出す（select / confirm / input / editor）。answered で PC 側の回答
curl -X POST http://127.0.0.1:47800/_dev/custom            # PC でしか操作できない画面（?end=1 で終了）
curl -X POST http://127.0.0.1:47800/_dev/resume            # PC で /resume（model で PC 側のモデル変更）
curl -X POST "http://127.0.0.1:47800/_dev/refuse-shutdown?on=1" # 「この Pi を終了」を断らせる（on=0 で戻す）
curl -X POST "http://127.0.0.1:47800/_dev/sub?kind=waiting"  # サブエージェント（下を参照）
```

サブエージェント: 「認証まわりのレビュー」は、起動時から pi-subagents のバックグラウンド実行（reviewer × 3。約10秒ごとに作業が進み、1人が先に終わる）と以前の実行（完了・失敗）を持っています。操作は実行・子の `actions` に従い、割り込む（作業記録にあなたの発言が入る）、後で伝える（次の一歩で入る）、停止（停止中 → 停止）、続きを依頼（`resumedFrom` つきの新しい実行）を再現します。`/_dev/sub?kind=…`:

| kind | 内容 |
|---|---|
| `parallel` | reviewer × 3 のバックグラウンド実行をもう1つ（既定は「認証まわりのレビュー」） |
| `waiting` | 親に質問中の子（既定は「API クライアントのリファクタ」→ 要対応に出る） |
| `chain` | 公式サンプルのチェーン scout → planner → worker（見るだけ・すべて停止。既定は「PiMate」。親は実行中になる） |
| `answer` | 質問中の子を再開（親が答えたことにする） |
| `finish` | 動いている子を最後まで進める |
| `hold` | 進行を止める / 再開する（スクリーンショット用） |
| `reset` | `subagents_reset`（実行なし） |

対象の Pi は `?i=<instanceId>` で選べます（省略時は先頭）。「--shout フラグを追加」の履歴には、RC の差分がない古い write（書き込んだ内容だけの表示）が入っています。新しい Pi の起動でフォルダに `missing` を含めると「見つからない」、`fail-message` を含めると「起動したが最初のメッセージを送れなかった」を再現します。

ネイティブの依存を追加するときは `npx expo install <pkg>` を使います。詳しくは [AGENTS.md](AGENTS.md) を参照してください。

### 送信の互換性

アプリは待機中に見えても `deliverAs: "steer"` を明示します。PC 側で先に作業が始まった場合にも followUp になりません。RC は受信時の `ctx.isIdle()` に応じて `deliveredAs: "prompt" | "steer"` を返します。既存の wire 値を使うため古い RC でも送信できます（古い RC は待機中も `steer` と返す場合がありますが、Pi 自体は通常送信します）。古いアプリ・CLI の省略時の busy followUp と明示的な followUp は互換性のため RC に残します。PC TUI の操作は変えません。

Pi が画像や本文の寸法注記を変換すると、反映済みでも停止時に未確認として残る場合があります。類似だけで届いたと推測せず、履歴を手動で確認してください。
