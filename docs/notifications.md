# M5c: 接続中のローカル通知

Android アプリ / PC Host **0.1.1**。FCM、Expo Push Service、Relay、foreground/background service は使いません。RC の既存イベントを Host が分類し、接続中のアプリが expo-notifications で端末内に表示します。

## 使い方と制限

設定 →「接続中の通知」をオンにすると、初めて OS の通知許可を要求します。起動しただけでは要求しません。Android 13 以降では許可が必要です。拒否・OS/チャンネルで無効にした場合は OS 設定の案内を表示します。許可を変更して戻ると再確認します。「入力待ち・要対応」「完了」「失敗」はそれぞれオフにでき、端末内に保存します。全体をオフにすると、PiMate が表示した通知も消します。

- **接続中の全 Host・全 Pi** が対象。選択していない Pi の履歴をアプリに読み込むことはありません。
- 前面で対象チャットを実際に表示中は通知しません。別画面・ドロワー・別 Pi の表示中は通知します。
- 通知タップは、ペアリング済み Host、実行中の Pi、通知時のセッション ID を再検証して親チャットへ移動するだけです。PC セッションの切り替え、回答、送信、子への指示はしません。古い通知・終了済み Pi・削除済み Host は説明画面になります。
- **アプリ終了・OS の休止・通信断中は届きません。** バックグラウンドは JS/WebSocket が生きている間だけの best effort です。未受信通知の蓄積・再送・常時起動保証はありません。
- 初回同期、履歴取得、再接続、セッション切り替え、subagents reset は通知を再生成しません。起動時点ですでに入力待ち・失敗だったものは一覧で確認してください。
- 通知は種類を示す固定文だけ。プロンプト、質問、ツール出力、ファイルパス、Host 名、認証情報を載せません。タップ用 data は opaque な host/instance/session ID のみ。Android チャンネルは `pimate-activity`（PRIVATE）。
- **旧 Host 0.1.0 では通知は使えませんが、チャットは使えます。** 設定に更新案内が出ます。PC パッケージ更新後、Pi の `/reload` と `/pimate restart` を実行してください。Host 0.1.1 の分類は従来の RC イベントを利用するため、RC 0.1.0 からでも利用できます。

## 通知対象

| 通知 | 判定 | 設定 |
|---|---|---|
| 親の入力待ち | `status` が新しく `waiting_input` になる（標準 select/confirm/input/editor） | 入力待ち・要対応 |
| 親の完了 | Host が開始を観測したターンで、最終 assistant `stopReason=stop`、`agent_settled.aborted=false` | 完了 |
| 親の失敗 | 同上、最終 assistant `stopReason=error` | 失敗 |
| 子の要対応・一時停止 | 既知の子が `waiting` / `paused` に変わる | 入力待ち・要対応 |
| 子の失敗 | 既知の子が `failed` に変わる | 失敗 |

中断・切断・終了理由不明・長さ制限・ツール単体のエラー・子の個別完了は通知しません。途中のモデルエラーが自動リトライで回復し最終回答が成功した場合は完了だけです。初めて現れた時点ですでに失敗/待ちだった子は履歴との区別ができないため通知しません。同じ run 更新で複数の子が変化した場合は1件（失敗 → 一時停止 → 要対応の優先順）にまとめます。未対応バックエンドや custom TUI の要対応は従来どおりアプリのカードで確認します。Pi の起動エラー・接続エラーも従来の画面内表示です。

## 実装

- Protocol v1 に任意 capability `HostInfo.alerts` と `watch_alerts` / `alert` を追加。旧 Host に未知のコマンドを送りません。
- Host は通知を希望する認証済み接続がある間だけ全 Pi の RC に接続。最初の snapshot は基準状態、以後のライブイベントだけ分類します。RC 再接続時は分類器も再初期化します。監視だけの場合 history は要求しません。
- `AlertTracker` は会話本文を保持せず、seq・ターン終端・状態遷移だけ追跡。アプリもイベント ID を上限1024件で重複排除します。通知を逃した場合に履歴で補完しません。
- OS 通知タップはルーター/保存 Host 読み込み後に処理。last response と live response を同一 ID でまとめ、処理済み last response を消します。`hello` の instance/session guard と購読後の session 検証により古い対象を誤って開きません。
