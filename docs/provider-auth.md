# スマホからのプロバイダー認証

**Android 0.1.5 / PC 0.1.7 以上が必要です。** アプリ・Host・対象 Pi の RC をすべて更新してください。

## 使い方

1. チャットで認証設定を変更する Pi を開き、設定 → **プロバイダーのログイン**へ進みます。
2. 対象のマシン・フォルダを確認し、プロバイダーと認証方法を選びます。会話や選択中の Pi は切り替えません。
3. ブラウザを開く場合は自分でボタンを押します。認証情報の取得・保存は PC の Pi 側で行います。

| プロバイダー | スマホでの操作 |
| --- | --- |
| OpenAI (`openai`) | API キー入力のみ |
| OpenAI Codex (`openai-codex`) | デバイスコードをスマホのブラウザへ入力して承認。PC 側が完了を受け取る |
| Anthropic (`anthropic`) | API キー入力、または Claude 認証後に表示されたコードを貼り付け |

OpenAI（`openai`）の ChatGPT ログインは削除しました（[#57](https://github.com/phni3j9a/PiMate/issues/57)）。OpenAI Codex（`openai-codex`）のログインは引き続き利用できます。既存の認証情報は自動削除せず、必要なら「ログアウト」で削除できます。古い PC が OpenAI の OAuth を返してもアプリには表示しません。

Pi とプロバイダーが提供する認証方式を使います。アカウント・組織側で機能が制限されている場合や、Pi 更新で手順が変わった場合は利用できないことがあります。API キーを保存しただけではキーの有効性は検証しません。

## 保存先とログアウトの範囲

- 対象は **通常の Pi CLI/TUI 1.2.0**。`getAgentDir()` の `auth.json`（既定 `~/.pi/agent/auth.json`、`PI_CODING_AGENT_DIR` に対応）を公開 `ModelRuntime` API で更新します。SDK が独自の `credentials` / `authPath` を注入した実行は対象外です。
- 同じエージェントディレクトリを使う **PC の Pi・ほかの Pi にも共通**です。現在の会話だけの設定ではありません。ログインも、そのプロバイダーの既存の保存情報を置き換えます。
- ログアウトは確認後に **保存されたそのプロバイダーの情報だけを削除**します。環境変数・`models.json`・起動時指定は変更せず、プロバイダー側のトークンも失効させません。そのため削除後も利用できる場合があります。
- トークンや入力したキーをスマホへ返したり、チャット・outbox・アプリの永続ストレージへ保存したりしません。入力欄は一時メモリのみです。ただし、自分でコピーしたコード は OS のクリップボード・ブラウザ履歴に残る可能性があるため共有しないでください。
- API キーは文字どおりに扱い、先頭 `!` のコマンド指定は拒否します。Pi が `$` を環境変数として解釈しないよう、PC で保存直前だけ標準の `$$` エスケープを適用します。

## 切断・中止・更新

- 起動中の Pi が必要です。Host だけが動いている状態では認証できません。
- **アプリ・Host・対象 Pi の RC をすべて更新**してください。Host と RC の両方の `providerAuth === true` を確認します。古い Host の短い RPC timeout では認証待機が途中で終わるため、RC だけの更新では有効にしません。
- 認証の進行情報は専用 RPC の応答だけで扱い、通常の会話イベントへ配信しません。クライアントは一度に1件の long-poll（最大25秒）を送り、変更または期限の応答後にだけ次を送ります。RC は再接続分を含め最大8件まで待機できます。
- 再接続時は認証状態を読み直します。開始応答を失っても `auth_list.flow` から進行中の処理を回復できます。キー・コード・ログアウト要求を自動で再送しません。
- 対話は最大15分です。画面を離れると中止を試みますが、すでに保存が始まっていれば中止できません。Pi の再起動・`/reload`・会話切替でも進行中の認証は破棄されます。保存中に切断・失敗した場合は「結果不明」として状態を確認します。
- 保存後は対象 Pi のモデル一覧を再取得します。認証情報は保存できてもモデルへの反映に失敗した場合は、再ログインを促さず Pi の再起動 / `/reload` を案内します。他の起動済み Pi の表示まで即時同期することは保証しません。

ワイヤー定義は [`packages/protocol/src/auth.ts`](../packages/protocol/src/auth.ts)、PC 側は [`auth.ts`](../packages/pimate/src/extension/auth.ts)、アプリ側は [`providerAuth.ts`](../apps/mobile/src/lib/providerAuth.ts) と [`provider-auth.tsx`](../apps/mobile/src/app/provider-auth.tsx) です。

## 検証

- 一時ファイル・fake provider による公開 `ModelRuntime` の保存・削除、入力検証、キャンセル・期限・保存競合・秘密情報の非配信を自動テストします。OAuth の開始直後のキャンセルでも後処理へ到達する回帰テストを含みます。
- アプリの宛先固定、旧 Host/RC、状態回復、結果不明時の非再送、複数フローの遅延応答と非永続化を単体テストします。開発用 fake Host の3プロバイダーのフローも通信テストします。
- OpenAI OAuth の拒否・旧 PC が返す認証方式の除外・既存認証情報の保持とログアウト、Codex / Anthropic / API キーの継続動作を回帰テストします。
- ChatGPT ログイン削除後に `npm run lint`・`npm run typecheck`・`npm test`（485件）が成功しました。
- 初回実装時の Android エミュレーター・配布パッケージ検証は [PR #52](https://github.com/phni3j9a/PiMate/pull/52) に記録しています。ChatGPT ログイン削除後の実アカウント認証・Android / iOS の画面操作は未検証です。既存のユーザー認証情報・物理スマホは変更していません。
